## 1. Purpose

This workflow establishes for Q040 the same guarded operating pattern used in Stability Inheritance: continuous safe execution between scientific gates, durable checkpoints, explicit evidence classes, refusal-preserving representation qualification, and a compute conveyor that is execution plumbing rather than scientific authority.

The workflow exists to prevent three failures:

1. outcome-guided construction of the recovery hypothesis;
2. accidental promotion of a candidate representation into admitted \(\chi\), \(Χ\), or \(Χ_{\mathrm{arc}}\);
3. automated continuation past a scientific decision simply because code can continue running.

## 2. Scientific object

Q040 investigates whether repeated perturbation changes finite-time recoverability around a representation-licensed scale-local baseline and, only if supported, whether any history-dependent change precedes slower-scale baseline migration or broader Stability-Architecture reorganization.

The candidate representation set is:

\[
\chi_S^{*}(t),\qquad
Χ_S(t),\qquad
Χ_{\mathrm{arc},S}(t),
\]

with \(\chi^{*}\) explicitly denoting a candidate scalar coordinate.

The candidate baseline lattice is:

\[
B_S^{\chi}(t),\qquad
B_S^{Χ}(t),\qquad
B_S^{Χ_{\mathrm{arc}}}(t),
\]

This ladder is inherited as a candidate from Market temporal-hierarchy work, not presumed universal.

## 3. Operating rule

The computational conveyor may execute only tasks explicitly marked \`READY\` in the frozen queue.

For each READY task it must:

1. execute the declared script only;
2. read the declared result object;
3. compare the returned disposition against an explicit frozen allow-list;
4. stop on any mechanical failure;
5. stop on any unlisted scientific disposition;
6. stop at any declared checkpoint;
7. preserve failures, refusals, invalid tests, and superseded routes;
8. never change task status or scientific interpretation by itself.

The queue is execution plumbing. It is not scientific authority.

## 4. Scientific intervention gates

The conveyor must stop and require explicit scientific adjudication before any of the following:

- removing the asterisk from \(\chi_S^{*}\);
- assigning a native observable directly to \(\chi\) by analogy;
- defining or materially changing \(\gamma_S\), \(\omega_S\), or a generalized scalar coordinate;
- defining a decisive \(Χ_{\mathrm{arc},S}\) construction;
- selecting a primary scale-local baseline operator \(\mathcal{K}_S\);
- selecting or changing perturbation-entry, reclaim, sustain, timeout, or episode-merging thresholds;
- selecting a primary recovery endpoint after outcome exposure;
- changing treatment of scheduled or unscheduled exogenous forcing \(\xi(t)\);
- changing the initial scale ladder after real Q040 exposure;
- changing native comparator families after real Q040 exposure;
- converting an exploratory/post-result observation into a prospective claim;
- opening real Q040 development outcomes before the frozen preregistration gate;
- opening any untouched P1 evidence before the P1 identity/freeze gate;
- overriding a REFUSED, INVALID_TEST, NEED_MORE_INFO, or native-equivalent disposition.

A scientific decision may create a new plan version, Plan Delta, queue identity, or preregistration identity. The old identity remains preserved.

## 5. Work allowed without scientific intervention

The following are mechanically safe when they do not alter frozen science:

- literature intake and citation/provenance maintenance;
- source identity, rights, checksums, and file manifests;
- reviewer-package assembly and rendering;
- synthetic known-truth implementation from already frozen definitions;
- test harnesses, unit tests, CI, schema validation, and deterministic reproducibility checks;
- code refactors that preserve declared inputs/outputs and frozen algorithms;
- dependency or transport repair before target exposure;
- logging and durable checkpoint updates;
- report generation from already frozen result objects;
- Function/Limit bookkeeping;
- mechanical adjudication formatting after the scientific disposition has been decided.

## 9. Recovery claim ladder

### R0: observed trajectory difference

Allowed:
> finite-time recovery trajectories differ.

### R1: history-dependent recovery dynamics

Requires history variables to add out-of-sample information beyond current state, shock magnitude, spacing, baseline motion, order-flow memory, activity/liquidity, volatility, and direction.

Allowed:
> finite-time recovery dynamics are history-dependent under the frozen observation/model class.

### R2: changed finite-shock recoverability

Requires a nonlocal quantity such as:
- finite-time return probability;
- independence time;
- transition/escape threshold;
- exit-time distribution;
- basin/viability proxy independently defined.

Allowed:
> finite-shock recoverability changed.

### R3: Stability-Architecture reorganization

Requires:
- independently admitted representation change in \(\chi\), \(Χ\), and/or \(Χ_{\mathrm{arc}}\);
- prospective relation to the later recovery/transition outcome;
- controls against moving-baseline, memory-only, forcing, and native-history explanations.

Repeated slower recovery alone cannot license R3.
